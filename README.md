# Подружки MAX — автоматизация канала и Mini App

Репозиторий проекта для автоматизации контента канала **«Подружки» в MAX**.

Проект постепенно развивается в сторону нескольких независимых направлений:

- автоматическая публикация постов по рубрикам;
- публикация новостей шоу-бизнеса;
- подбор и ротация фотографий;
- Mini App для интерактивных тестов;
- параллельная публикация контента в Telegram;
- хранение структурированных данных для отдельных рубрик.

Проект находится в активной разработке, поэтому структура репозитория будет постепенно меняться по мере появления новых рубрик и Mini App.

---

## Что делает проект

Основная задача проекта — максимально автоматизировать работу канала:

1. По расписанию определяется, какую рубрику нужно публиковать.
2. Для рубрики подготавливается текст.
3. Подбирается подходящее изображение:
   - сначала из собственной базы фотографий;
   - если подходящего изображения нет — через Pexels.
4. Пост публикуется в MAX.
5. При наличии настроенного Telegram-бота тот же материал дополнительно публикуется в Telegram.
6. GitHub Actions запускает необходимые процессы автоматически по расписанию.

Отдельно работает новостной блок: он получает свежие новости шоу-бизнеса, фильтрует их, делает рерайт и публикует подходящие материалы.

# Основные части проекта

## Рубрики

Основная логика публикации рубрик находится в:

`rubric_post_to_max.py`

Этот скрипт:

- определяет время публикации;
- выбирает нужную рубрику;
- читает настройки рубрик из `rubrics.json`;
- генерирует текст поста через YandexGPT;
- подбирает изображение;
- публикует пост в MAX;
- при настроенном Telegram дополнительно отправляет пост в Telegram.

Список и настройки рубрик находятся в:

`rubrics.json`

История уже опубликованных рубрик хранится в:

`posted_rubrics.json`

Этот файл используется для того, чтобы система не публиковала одну и ту же рубрику повторно.

# Mini App

Папка:

`miniapp/`

Сейчас в проекте находится Mini App с тестами.

Основные файлы:

- `miniapp/index.html` — страница приложения;
- `miniapp/app.js` — логика приложения;
- `miniapp/style.css` — оформление;
- `miniapp/tests/` — тексты тестов.

Особенность текущей реализации:

**«Тест дня» в канале и тест в Mini App используют один и тот же исходный файл теста.**

Это позволяет не хранить название и описание одного теста в двух разных местах и снижает риск расхождения между постом и приложением.

В будущем Mini App будет несколько.

Поэтому папка `miniapp/` в дальнейшем может быть преобразована в структуру с отдельными папками для каждого приложения.

# Данные рубрик

В корне репозитория сейчас находятся JSON-файлы, которые используются как структурированные данные для различных рубрик.

В частности:

### Эзотерические рубрики

- `numerology.json` — данные для нумерологии;
- `omens.json` — приметы и поверья;
- `palmistry.json` — данные по хиромантии;
- `tarot_deck_78.json` — колода Таро из 78 карт.

### Женская тематика

- `max_women_holidays.json` — женские праздники и даты, используемые в утреннем посте;
- `women_success_stories.json` — истории успешных женщин для соответствующей рубрики.

### Фотографии

- `photo_bank.json` — собственная база фотографий для рубрик.

### Настройки рубрик

- `rubrics.json` — расписание и настройки рубрик;
- `posted_rubrics.json` — история опубликованных рубрик.

Структура хранения JSON в дальнейшем будет отдельно пересмотрена.

Планируется разделить данные по категориям, так как по мере развития проекта количество JSON-файлов будет расти.

# Работа с фотографиями

За подбор изображений отвечают:

- `photo_bank.py`
- `photo_bank.json`

Система поддерживает собственную базу фотографий.

Если для конкретной рубрики есть подходящее изображение в собственной базе, используется оно.

Если изображения нет, система может обратиться к Pexels.

Таким образом, собственная база фотографий постепенно может расширяться, не ломая существующую автоматизацию.

`photo_bank.py` также отвечает за ротацию фотографий, чтобы одно и то же изображение не использовалось постоянно.

# Автоматический отбор фотографий

`fetch_photo_candidates.py`

Это вспомогательный скрипт, созданный для автоматического отбора кандидатов фотографий для рубрик.

Он относится скорее к инструментам обслуживания проекта, чем к основной логике публикации.

Файл пока сохраняется в репозитории.

Его дальнейшая судьба будет определена после того, как станет понятно, нужен ли он для регулярной работы или был одноразовым инструментом.

# Новости

Папка:

`news/`

Новостной блок пока является отдельной частью проекта.

Он предназначен для автоматической работы с новостями шоу-бизнеса.

Основной процесс:

1. `gdelt_search.py` получает свежие статьи через GDELT.
2. `filter_articles.py` отбирает материалы, соответствующие тематике проекта.
3. `rewrite_and_post.py` делает рерайт статьи через YandexGPT.
4. Готовый материал публикуется в MAX.
5. При настроенном Telegram тот же пост может быть опубликован и там.
6. `posted_news.json` хранит уже опубликованные новости.

### Основные файлы

`news/gdelt_search.py`  
Поиск свежих материалов через GDELT.

`news/filter_articles.py`  
Фильтрация найденных статей по тематике шоу-бизнеса.

`news/rewrite_and_post.py`  
Рерайт и публикация новостей.

`news/max_common.py`  
Общие функции для работы с MAX.

`news/posted_news.json`  
История опубликованных новостей.

На данный момент структура папки `news/` считается отдельной подсистемой и не изменяется без необходимости.

# Telegram

`telegram_common.py`

Telegram является дополнительным каналом публикации.

Основная площадка проекта — MAX.

Если в GitHub Secrets настроены:

- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID`

после успешной публикации материал также может отправляться в Telegram.

Для Telegram используется тот же основной текст и изображение, что и для MAX.

Дополнительно текст адаптируется под Telegram и к нему могут добавляться хэштеги.

Если Telegram не настроен, публикация в Telegram просто пропускается.

# GitHub Actions

Автоматизация запускается через GitHub Actions.

Workflow находятся в:

`.github/workflows/`

Текущие workflow:

### `rubric_post.yml`

Запускает публикацию рубрик.

Скрипт регулярно проверяет расписание и определяет, пора ли публиковать очередной пост.

### `news_post.yml`

Запускает автоматическую обработку и публикацию новостей.

### `gdelt_test.yml`

Используется для тестирования получения данных через GDELT.

### `fetch_photo_candidates.yml`

Запускает инструмент автоматического отбора кандидатов фотографий.

# Переменные и секреты

Секретные значения не должны храниться непосредственно в исходном коде.

Для работы автоматизации используются переменные окружения и GitHub Secrets.

В частности, могут использоваться:

- `MAX_BOT_TOKEN`
- `MAX_CHAT_ID`
- `PEXELS_API_KEY`
- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID`
- `YANDEX_GPT_API_KEY`
- другие необходимые ключи API.

**Секреты нельзя добавлять в репозиторий.**
