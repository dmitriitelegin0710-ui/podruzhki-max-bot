# MAX Mini App — Сканер состава

Фотографируешь этикетку → получаешь понятную рекомендацию (полезно / не
полезно) с учётом фильтра: обычный / для детей / для аллергиков / для ПП.
Технология анализа (Yandex Vision) пользователю не показывается — только
готовый вывод.

## Структура

```
scan-analyzer/
├── index.html
├── app.js
├── style.css
└── README.md
```

Работает в паре с бэкендом `scan_backend/server.py` (в корне репозитория) —
без него мини-апп не запустится, весь анализ и платежи идут через него.

## Настройка перед публикацией

1. Разверните `scan_backend/server.py` на любом хостинге с HTTPS
   (см. `scan_backend/README.md`).
2. В `app.js` замените:
   ```js
   const BACKEND_BASE_URL = "https://ВАШ-БЭКЕНД.example.com";
   ```
   на реальный адрес развёрнутого бэкенда.
3. Загрузите папку на тот же хостинг, где лежит `miniapps/tests`
   (сейчас это `https://xn--d1aeghrfjy.online/max/`), например по пути
   `.../max/scan/`.

## Локальная проверка

Нужен HTTP-сервер (браузер блокирует запросы напрямую с file://):

```
python -m http.server 8000
```

Открыть `http://localhost:8000/`. Внутри MAX `window.WebApp` подставится
автоматически; вне MAX используется резервный `device_id` из localStorage.

## Как это добавить в канал

В `rubric_post_to_max.py` есть готовая функция `build_scan_app_attachments()`
(по аналогии с `build_test_dnya_attachments`) — она создаёт кнопку
`open_app`, которая откроет этот мини-апп прямо из поста в канале.
