# Backend — Сканер состава

Один файл `server.py` (Flask). Хранит баланс сканирований в SQLite
(`scans.db`, создаётся сам рядом со скриптом при первом запуске),
дёргает Yandex Vision, продаёт пакеты сканирований через ЮKassa.

## Деплой на reg.ru (обычный хостинг, не VPS)

reg.ru поддерживает Python-приложения на обычном хостинге через **Passenger** —
для этого в комплекте есть файл `passenger_wsgi.py` (уже написан, нужно
только его дозаполнить).

Сайт «Подружки» уже занимает корень домена, поэтому бэкенду нужен **отдельный
поддомен** — Passenger привязывается на уровне сайта/поддомена, а не
произвольной папки внутри существующего PHP-сайта.

### Шаг 1. Создать поддомен
В панели reg.ru (или ISPmanager) — раздел «Домены» → «Добавить поддомен».
Например: `api.xn--d1aeghrfjy.online` (или `scan.` — как удобно).
Он создаст отдельную папку, например `~/data/www/api.xn--d1aeghrfjy.online/`.

### Шаг 2. Залить файлы
Через FTP или SSH скопировать содержимое папки `scan_backend/` (все три
файла: `server.py`, `passenger_wsgi.py`, `requirements.txt`) в корень этого
поддомена — то есть прямо в `~/data/www/api.xn--d1aeghrfjy.online/`.

### Шаг 3. Виртуальное окружение и зависимости
По SSH (доступ к SSH обычно есть у обычного хостинга reg.ru, логин/пароль —
в личном кабинете, раздел «Доступ SSH»):
```bash
cd ~/data/www/api.xn--d1aeghrfjy.online
python3 -m venv ~/data/scanenv
source ~/data/scanenv/bin/activate
pip install -r requirements.txt
```

### Шаг 4. Включить Python-приложение в панели
В ISPmanager (или аналогичной панели reg.ru) — раздел **Python** (или
WSGI-приложения) → указать:
- Корень приложения: `~/data/www/api.xn--d1aeghrfjy.online`
- Стартовый файл: `passenger_wsgi.py`
- Интерпретатор: путь до `~/data/scanenv/bin/python`

Если такого раздела в панели нет — попросите поддержку reg.ru включить
Passenger/Python для этого поддомена, они делают это по запросу.

### Шаг 5. Заполнить секреты
Открыть `passenger_wsgi.py` **прямо на сервере** (через FTP/SSH-редактор,
не в репозитории) и вписать реальные значения вместо `ВАШ_ТОКЕН_БОТА` и
остальных плейсхолдеров — см. список ниже. Это самое надёжное место для
секретов на shared-хостинге, т.к. панель reg.ru обычно не даёт удобно
задавать переменные окружения для Python-приложений.

### Шаг 6. Проверить
После перезапуска приложения (кнопка «Перезапустить» рядом с Python-
приложением в панели) открыть `https://api.xn--d1aeghrfjy.online/api/health`
— должно вернуться `{"ok": true}`.

### Шаг 7. Подставить адрес в мини-апп
В `miniapps/scan-analyzer/app.js`:
```js
const BACKEND_BASE_URL = "https://api.xn--d1aeghrfjy.online";
```

## Список секретов, которые нужно получить и вписать

```
MAX_BOT_TOKEN          — токен вашего бота в MAX
YANDEX_VISION_API_KEY  — API-ключ сервисного аккаунта Yandex Cloud
YOOKASSA_SHOP_ID        — shopId из личного кабинета ЮKassa
YOOKASSA_SECRET_KEY     — секретный ключ ЮKassa
RETURN_URL              — куда вернуть пользователя после оплаты (ссылка на мини-апп)
```

## Что нужно доделать перед запуском в бой

1. ~~Подключить скрипт анализа~~ — уже сделано: `call_yandex_vision_ocr()`
   в `server.py` — это ваш проверенный код из `test_yandex_vision.py`,
   адаптированный под приём байтов фото вместо пути к файлу на диске.
2. **Настроить пакеты** — список `PACKAGES` в начале файла: количество
   сканов и цена. Сейчас три пакета-заглушки (5 / 15 / 50 сканов).
3. **Настроить ЮKassa вебхук.** В личном кабинете ЮKassa → HTTP-уведомления
   → указать `https://ваш-бэкенд/api/pay/webhook`.
4. **(Опционально) доработать логику рекомендации.** Сейчас
   `build_recommendation()` — простой разбор по ключевым словам
   (пальмовое масло, глутамат натрия, аллергены и т.д.). Можно заменить
   на вызов YandexGPT для более гибкого анализа состава — тогда OCR
   передаёт текст в модель с промптом вида "оцени состав для контекста:
   {filter}" и модель возвращает вердикт+рекомендации.

## Ручки API

- `GET  /api/balance` — баланс сканирований пользователя
- `POST /api/analyze` — `multipart/form-data`: `image`, `filter` (none/kids/allergy/healthy)
- `POST /api/pay/create` — `{"package_id": "pack_5"}` → `{"confirmation_url": "..."}`
- `POST /api/pay/webhook` — вызывается ЮKassa автоматически
- `GET  /api/health` — проверка живости

Идентификация пользователя (заголовок `X-Init-Data` или параметр
`device_id`) устроена так, что не требует правок при переходе с
тестового режима (браузер) на прод (внутри MAX) — оба варианта уже
поддержаны в одном коде.
